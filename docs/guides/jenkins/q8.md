# Operating the Jenkins Controller: State, Configuration, Backups and Upgrades

> **Engineering scenario:** The controller must be upgraded without losing job history, credentials, Pipelines or agent registration. Build a rollback and disaster-recovery plan that recognizes the stateful parts of Jenkins.

## Why Jenkins controller recovery differs from a stateless web service

The controller stores much of its operational state under `JENKINS_HOME`: global configuration, installed plugins, job/build metadata, Pipeline state, credentials material, and history. Containerizing it doesn't make this state disposable. A load balancer distributing writes across two unrelated controllers is **not** a transparent Jenkins active-active architecture. Jenkins core is not generally operated as multiple interchangeable replicas sharing the same writable home directory.

### Configuration as Code (JCasC)

The Configuration as Code plugin reads YAML for supported controller/plugin configuration, often from `CASC_JENKINS_CONFIG`. It improves reviewability and bootstrap repeatability, but not every plugin/global state is represented by one portable YAML file. JCasC can **supplement**, not replace, a complete `JENKINS_HOME` recovery strategy and plugin compatibility plan.

```yaml
jenkins:
  numExecutors: 0
  systemMessage: "Managed by reviewed configuration."
  mode: NORMAL
```

This is a minimal example and requires an installed, compatible JCasC plugin. **Do not** commit real secret values in YAML. Use an approved secret source/resolver, protect the repository and validate expansions in a sandbox.

### Backup invariants

- Capture a consistent filesystem snapshot or a quiesced copy of required `JENKINS_HOME` content.
- Include versioned plugin inventory and configuration; build history/artifacts according to retention requirements.
- Store encryption key material separately with strong access controls. Jenkins documentation recommends protecting `master.key` independently of routine backups; restores need compatible key material for encrypted data.
- Verify backup consistency, confidentiality, restore completeness and **actual measured RTO/RPO** with a disconnected environment.
- Avoid restoring production credentials into a testing environment that has network access to real production systems.
- A snapshot does not undo secrets leaked before it was taken.

### Safe upgrade runbook

1. Inventory Jenkins core/LTS line, Java runtime, plugin dependencies, controller image, storage and integrations.
2. Read changelogs, security advisories and minimum Java requirements for the **selected versions**. Don't assume all LTS versions share requirements.
3. Freeze or drain risky releases. Observe running Pipelines and decide whether to allow completion, interrupt or resume later.
4. Take and verify a consistent backup and independently secured key material.
5. Upgrade in a staging clone with equivalent plugins and sanitized credentials. Check real Pipeline library/job compatibility.
6. Roll canary workloads through the upgraded environment, validate agents, webhooks, SCM, credentials binding and artifact publication.
7. Apply an approved maintenance window to production, observe heap, logs, queue latency, plugin loading and business workflows.
8. Rollback requires restoring compatible persisted state, not blindly downgrading binaries after schema/plugin migrations.

## Fault scenarios

- **Disk full:** controller cannot persist logs/state. Stop uncontrolled disk growth, identify large artifacts/workspaces and archive/retire safely; do not delete arbitrary `program.dat`, job history or secret material during an incident.
- **Plugin mismatch:** startup logs show missing classes/failed dependencies. Restore a compatible core/plugin set after reading the full dependency error; forcing the plugin directory by hand can compound corruption.
- **Controller restart during build:** some resumable steps may continue, others fail if their agent/workspace or external step isn't recoverable. Test restart behavior for the actual plugin set.
- **Lost encryption key:** encrypted credentials may become unrecoverable despite intact `JENKINS_HOME` backups.

### Read-only checks

```bash
# Systemd deployment only; use pod logs for a container installation.
systemctl status jenkins
journalctl -u jenkins --since '30 min ago' --no-pager
df -h
df -i
free -h
# In Manage Jenkins: plugin inventory, system logs, nodes and warnings
```

### Spoken explanation

> “Jenkins is a stateful controller. I'd keep builds off the controller, version its configuration/plugins, back up home data consistently, secure master key material separately and exercise restores in an isolated environment. Before an LTS upgrade I'd validate Java and plugin compatibility, agent connectivity, Pipeline resume behavior and rollback constraints. One active controller with recoverable state is not the same as a magically active-active Jenkins cluster.”
